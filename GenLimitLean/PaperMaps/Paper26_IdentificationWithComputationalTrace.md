## Statements and representations

A positive stream covers exactly the target language and may repeat words. An accepting trace includes the initial and final configurations. A single insertion, deletion, or substitution costs one edit. The length cutoff in Definition 5 measures the **input word**. The relative-error denominator measures the **full true trace**, including its endpoints as in Example 2. Every state named by a corrupted observation belongs to the finite control set, including on short words. [Edit scripts](../GenLimit/Paper26_IdentificationWithComputationalTrace/Edits.lean) · [Presentations](../GenLimit/Paper26_IdentificationWithComputationalTrace/FiniteControl.lean)

* Theorem 3.1 uses a single read/write tape, a fixed input alphabet with injective nonblank codes, and natural-number names for states and tape symbols. The finite partial transition table rejects on a missing instruction. The operational accepting-run relation is proved equivalent to recognition by legal traces. [Recognizer and operational semantics](../GenLimit/Paper26_IdentificationWithComputationalTrace/PerfectTrace.lean)
* The robust results use the fixed binary input alphabet of Section 4. For 4.3 the stack alphabet is binary, and each instruction can pop, keep, or push one symbol. The transition sees the next input symbol or the end marker, may leave the input unread, and accepts on empty input and empty stack. For 4.5 the machine has the read-only input tape and binary work tape of Appendix B.3, with independent head moves. A distinct input blank indicates the region outside the word. [Pushdown model](../GenLimit/Paper26_IdentificationWithComputationalTrace/Pushdown.lean) · [Two-tape model](../GenLimit/Paper26_IdentificationWithComputationalTrace/Turing.lean)
* A successful learner stabilizes to one fixed hypothesis with the correct language, as required by Definitions 1, 3, and 4. The DFA hypothesis has an explicit DFA product. The robust pushdown and TM learners output a finite description consisting of short positive words and a finite collection of transition tables. An executable bounded simulation of every table, with the common time bound increased successively, recognizes their intersection on long inputs. This choice of output representation avoids an inclusion oracle. [Output code and semantics](../GenLimit/Paper26_IdentificationWithComputationalTrace/FiniteError.lean)
* The diminishing-rate theorem accepts the paper's modulus for every real rate in ((0,1)). The learner needs only its values at reciprocal integer rates. Both negative results quantify over arbitrary hypothesis names and denotation maps, so they cover computable learners as well. [Rate conversion](../GenLimit/Paper26_IdentificationWithComputationalTrace/Diminishing.lean) · [Reduction to Gold's locking theorem](../GenLimit/Paper26_IdentificationWithComputationalTrace/Indistinguishable.lean)

## Proof correspondence

**Theorem 4.3.** The upper proof marks every instruction incident to a hidden state and enough consuming instructions to retain the input-length cutoff. A pushdown run gives a binary derivation and each typed derivation can be executed with the original stack and unread-input suffix. Shortening preserves the ordered list of protected instructions. A shortest such derivation has size at most a computable factor times one plus its mark count. An unobserved state occurrence needs an edit, so choosing the rate from that factor gives a state bound depending only on the observed states and the known cutoff. This proves the theorem independently of the numerical bound of Lemma 4.4. The lower proof uses blocks of integer length and performs the distinguishing count during the final pops. [Parsing](../GenLimit/Paper26_IdentificationWithComputationalTrace/StackParsing.lean) · [Compression](../GenLimit/Paper26_IdentificationWithComputationalTrace/StackCompression.lean) · [State bound](../GenLimit/Paper26_IdentificationWithComputationalTrace/StackRadius.lean)

**Theorem 4.5.** The proof of Lemma B.2 in Appendix B.3 splits on computation length to apply an error bound whose stated hypothesis concerns input length. A short word can have a long computation. The Lean proof handles all short words through finite memorization and applies the bound only to long words. On those words the observed trace length plus the edit budget also bounds the true computation time. In the negative construction, the common padding runs **before** the accepting halt, and Lean checks equality of the full surviving configurations. Both theorem conclusions follow. [Finite-control bound](../GenLimit/Paper26_IdentificationWithComputationalTrace/ControlBound.lean) · [Padding and error estimate](../GenLimit/Paper26_IdentificationWithComputationalTrace/UnaryTM.lean)
