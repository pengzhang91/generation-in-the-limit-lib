# IRStatement file structure

IRStatement reads each theorem's full type directly from Lean. A grammar in [GF](https://www.grammaticalframework.org/), the Grammatical Framework ([references](README.md#references)), writes it as controlled English, the IR statement. The checker parses that English back and asks the Lean kernel to compare it with the declaration. Web pages show each statement three ways: the paper's words, the IR statement and the Lean code.

## Directory map

```text
IRStatement/
├── Grammar/
│   ├── IR.gf              The grammar: 158 rules (abstract syntax)
│   ├── IREng.gf           English for each rule
│   └── IRLean.gf          Lean for each rule
├── Check.lean             #check_statement: the kernel comparison (38 lines)
├── Export.lean            #ir_export: a declaration's full type as JSON
├── Glossary.lean          #ir_glossary: a definition stated as a theorem, proved by Iff.rfl or rfl
├── Vocabulary.lean        Three Lean devices for English phrases with no library constant
├── Scripts/
│   ├── runner.py          Runs Lake and GF; lists the declarations of each paper's Overview.lean
│   ├── selector.py        Chooses one GF tree per declaration from the JSON export
│   ├── reader.py          Writes and checks the readings; --all for every paper, no option for a quick test on P01
│   ├── glossary.py        The same for the definitions behind the labels
│   ├── cards.py           RULE-CARDS.md from the saved rule usage of both full runs
│   ├── pairs.py           MINIMAL-PAIRS.md: small edits of P01 readings, judged by Lean
│   ├── throughout.py      Shared settings of a page ("Setting A.")
│   ├── unfolding.py       Reads Unfolding.tsv and checks its quotations against the paper
│   ├── quotes.py          Fetches papers, checks every quotation, renders it with pandoc
│   └── web.py             Builds Web/ from checked pages, quotations and the Lean source
├── Tables/
│   ├── Frames.tsv         174 sentence frames: “𝒢 *achieves time vector* t on 𝒞”
│   ├── Renaming.tsv       Display names of variables and named terms (180 rows)
│   ├── Unfold.tsv         10 definitions always shown by their bodies, in every paper
│   ├── Unfolding.tsv      Per paper and constant: show the body or keep the label (603 rows)
│   └── RuleTiers.tsv      Each rule's tier, what to check, and who signed it
├── PaperStatements/       Pxx.json: verbatim quotations of each paper, per declaration
```

Outside this folder (paths from the repository root):

| File | Role |
| --- | --- |
| `GenLimitLean/lakefile.toml` | Declares this folder as the Lean library `IRStatement` |
| `GenLimitLean/GenLimit/PaperXX_*/Results/Overview.lean` | The declarations that are read |
| `registry/papers/PXX.json` | Titles, authors, editions and PDF hashes |

## Follow one reading through the files

P39 Theorem 3.15 reads, in full:

> Let 𝓛 be an indexed family of languages L_0, L_1, L_2, … ⊆ ℕ. Each L_i is infinite. 𝓛 has a membership oracle. Let x be a sequence of natural numbers. Let z ∈ ℕ.
>
> Suppose that the set of values of x is exactly L_z.
>
> Then 1 / 2 ≤ *patient lower density*(𝓛, x, z).

1. **Lean.** The declaration is `theorem_3_15` in `GenLimitLean/GenLimit/Paper39_DenseGeneration/Results/Overview.lean`, line 27:
   `(O : OracleFamily) (stream : ℕ → ℕ) {z : ℕ} (hP : Presents stream (O.language z)) : (1 / 2 : ℝ) ≤ PatientMachine.patientLowerDensity O stream z`.
2. **Export.** `#ir_export` in [Export.lean](Export.lean) prints this type as JSON. `Presents` is one of the ten definitions in [Unfold.tsv](Tables/Unfold.tsv) that every paper shows by its body, so the export contains `Set.range stream = O.language z` instead.
3. **Selection.** [selector.py](Scripts/selector.py) chooses the tree. [Unfolding.tsv](Tables/Unfolding.tsv) keeps *patient lower density* as a label: it is the lower density of the paper's patient-scope algorithm, and the row cites the paper. [Renaming.tsv](Tables/Renaming.tsv) renames `stream` to x (a row for every paper) and, for P39, `O` to the paper's 𝓛. The constant `patientLowerDensity` gets the label *patient lower density* from its name. It is a function, not a claim, so [Frames.tsv](Tables/Frames.tsv) has no sentence for it, and it reads *patient lower density*(𝓛, x, z).
4. **English.** `reader.py` compiles the grammar with this reading's lexicon of names (𝓛, x, z and the labels), and GF writes the English. Each sentence comes from one rule: `LetFamily` writes the first three sentences for the single binder `O : OracleFamily`, `ValuesExactly` writes “the set of values of x is exactly L_z”, and `Le`, `Div` and `LblApp` write the conclusion. The reading is saved in [Readings/P39.md](Readings/P39.md).
5. **Check.** GF parses the saved text and must find exactly one tree, the selected one. It renders the tree as Lean:
   `∀ («𝓛» : GenLimit.OracleFamily), ∀ (x : ℕ → ℕ), ∀ (z : ℕ), ∀ (_ : Set.range x = «𝓛».language z), (1 / 2) ≤ GenLimit.PatientMachine.patientLowerDensity «𝓛» x z`.
   `#check_statement` asks the kernel whether this equals the declaration's type. It does: the names O, stream and 𝓛, x are only bound-variable names, `Presents` unfolds to the range equation, and `1 / 2` is a real number because the right-hand side is. [Readings/RUN-LOG.md](Readings/RUN-LOG.md) records the result and the page's SHA-256.
6. **Labels.** The glossary entry of *patient lower density* uses the definition's own parameter names. It reads “By definition, *patient lower density*(O, x, z) = *relative lower density*(*generator first*(x, *output*(O, x)) ∩ L_z, L_z, *oracle family infinite*(O, z)).” It is checked the same way against the definition. See [Readings/Glossary/P39.md](Readings/Glossary/P39.md).
7. **Web.** `web.py` builds [Web/P39.html](Web/P39.html) only if the log records a pass for the page's SHA-256. It adds the paper's Theorem 3.15 from [PaperStatements/P39.json](PaperStatements/P39.json), “The patient-scope algorithm achieves the optimal lower density of 1/2.”, checked by `quotes.py` against the arXiv v2 PDF and its LaTeX source. The paper says “optimal”, but the IR statement shows only the lower bound 1 / 2 ≤ …; this is the kind of difference a reviewer finds by comparing the two. The paper's sentence next to the IR statement is what a reviewer compares.
8. **Rules.** The reading uses 19 rules, among them `LetFamily`, `ValuesExactly`, `LblApp`, `Le` and `Div`. Their cards are in [RULE-CARDS.md](RULE-CARDS.md); the count comes from `Readings/RULE-USAGE.json`.

## Change how a definition reads

There are five ways. Pick the one that gives the effect you want; it is usually one row in one file.

| Effect | Change | Review |
| --- | --- | --- |
| 1. Read a predicate as a short sentence instead of *label*(X, Y) | A row in [Frames.tsv](Tables/Frames.tsv) | Yes, that row |
| 2. Show the definition's body instead of its label, or keep the label | A row in [Unfolding.tsv](Tables/Unfolding.tsv) (one paper) or [Unfold.tsv](Tables/Unfold.tsv) (every paper) | No: the kernel checks the unfolding |
| 3. Use the paper's letter for a variable or a named term ("Let K = …") | A row in [Renaming.tsv](Tables/Renaming.tsv) | No: only names change |
| 4. Change the words of the label itself | No table; see below | Depends on the way |
| 5. Give the constant its own English wording | A new GF rule | Yes, that rule's card |

1. **Frame.** The columns are `paper`, `constant`, `frame` and `why`. In the frame, `{label}` is the label and `{1}`, `{2}`, … are the shown arguments in Lean's order. The other words must be plain lower-case words, not the grammar's connectives or quantifier words (and, or, not, every, …). For example, P13's frame `{1} {label} {3} on {2}` turns *achieves time vector*(𝒢, 𝒞, t) into “𝒢 *achieves time vector* t on 𝒞”. The kernel checks which argument goes where. A person checks that “on” names the right role, by reading the label's glossary entry.
2. **Unfold or keep.** The columns are `paper`, `constant`, `decision` (`unfold` or `keep`), `page`, `evidence` and `reason`. A `keep` because “this is the paper's term” must cite the paper: the PDF page and verbatim TeX. `reader.py` checks the citation against the PDF and the source, and stops if it fails. To unfold a definition in every paper, add it to [Unfold.tsv](Tables/Unfold.tsv) (columns `definition`, `local word`, `why`).
3. **Names.** The columns are `paper`, `Lean name`, `display name` and `why`.
   - A binder name renames that variable in every reading of the paper (P13: F → 𝒞).
   - A full constant name gives a named term headed by that constant the paper's symbol (P13: m⋆).
   - A row with an empty `paper` applies to every paper (stream → x).
4. **Label words.** A label is made from the Lean name by `label_words` in [selector.py](Scripts/selector.py); no table overrides it for one constant. There are three ways:
   - Rename the constant in the Lean library. This is the cleanest, but it changes tracked files.
   - Add a frame (way 1) to put role words around the label.
   - Add an override table to the selector. Then a label says more than the Lean name, so a person must review every row. Discuss this before doing it.
5. **New rule.** Add the rule to [IR.gf](Grammar/IR.gf), [IREng.gf](Grammar/IREng.gf) and [IRLean.gf](Grammar/IRLean.gf). Make [selector.py](Scripts/selector.py) choose it, and give it the tier `domain` in [RuleTiers.tsv](Tables/RuleTiers.tsv). An example is `KMGenerator`, “the membership-query generator for O”.

The ways need not be combined:

- A definition unfolded on a paper no longer appears there as a label, so its frame is not used on that paper.
- Names are independent. A definition can have a frame, and its readings can still use the paper's letters.
- A constant with its own rule is no longer shown as a label, so frames and unfolding no longer apply to it.

The glossary at the end of each page is read with the same grammar, labels and frames, so the changes apply there too.

After a change, run from the repository root:

```sh
D=GenLimitLean/IRStatement
python3 $D/Scripts/reader.py --write --papers 13  # try one paper: rewrites and checks P13, writes no log
python3 $D/Scripts/reader.py --write --all        # every paper, with the log, about 10 min
python3 $D/Scripts/glossary.py --write            # the glossary
python3 $D/Scripts/web.py                         # the web pages, about 3 min
```

A run with `--papers` writes no log, and `web.py` shows a page only if the log records a pass for its exact bytes, so finish with `--all`. If Lean rejects a reading, its page lists the declaration without a reading, with the reason; a wrong reading is never published.
