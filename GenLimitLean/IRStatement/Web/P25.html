How to read the IR statements
  • “Let …” introduces an object, and “Suppose that …” adds an assumption. Both stay in force to the end of the text, or of the bullet they are in.
  • “There is T ∈ ℕ, depending only on …, with the following property.” chooses T, and the rest of the text is the property; when the property is a list, it reads “with the following properties:”. Lean checks the list of dependencies. The list is shown only when the property opens with a new variable (“Let …” or “for every …”), so that the reader sees that T does not depend on it. Otherwise T may depend on everything above, and the list is left out.
  • “All of the following hold:”, “The following are equivalent:” and “At least one of the following holds:” are followed by bullets.
  • A word in italics is the label of a Lean constant, made from its name; point at it to see the constant. A label with one argument reads “X is label”, otherwise label(X, Y, …) with Lean's argument order. Some labels read as a short sentence instead, such as “𝒢 achieves time vector t on 𝒞”; the label's definition in the glossary uses the same sentence. Its negation reads “X is not label …” when the sentence has “is”, and again takes no quantifier after it.
  • “Let K = …” names a term that occurs several times. (x, y) is a pair, [x, y] a list, and () the only element of the one-point type. {0, …, k − 1} is Lean's Fin k. ⟨x⟩ is x as an element of a subtype, such as C(z) in the range of C; Lean supplies the proof of membership. “A member of S” is an element of the set S as a type, and “the set F” is a finite set F used as a set.
  • “Let t ≥ T.”, “for every t ≥ T”, “for every i < n” and “there is i < n such that” range over natural numbers.
  • A proof passed to a label is not shown when Lean can prove it from the assumptions. “label(X, Y) does not hold” and A ⊈ B are negations; no quantifier follows “does not hold”. Many names follow the paper (𝒞, ℋ, t⋆, …), to make reading the two side by side easier; each statement still says what its names stand for.
  • A statement that begins with “Setting A.” begins with the sentences of Setting A, listed under “Throughout”. The checker puts them in place of the mark.
  • A label with a dotted underline links to its definition in the glossary at the end of the page. A definition reads “By definition, … if and only if …”; Lean proves it by Iff.rfl, so it is the label's definition, unfolded once.
  • {x(n) : n < t} is the set of the first t terms of x, and ∖ is set difference. “O has a membership oracle” means that O comes with a correct test for x ∈ Li.

The paper’s setting (3)

  • Let 𝒳 be a countable universe of strings. For instance, if Σ is a finite alphabet (e.g., {a,b,…,z}), then 𝒳=Σ* can be the set of all finite-length strings formed by concatenating symbols from Σ. We define a language L as an infinite subset of 𝒳.

    p. 10

  • Let ℒ={L1,L2,…} be a collection of languages, 𝔾=(𝔾n) be a generating algorithm, and K∈ℒ be some target language. A randomized algorithm 𝔾 is said to generate from K in the limit if, for all enumerations of K, with probability 1, there is some n⋆∈ℕ such that for all steps n≥n⋆, the algorithm’s output satisfies 𝔾n(Sn)⊆(K\Sn), where Sn is the set of the first n elements given in the input. The collection ℒ allows for generation in the limit if there is an algorithm 𝔾 that generates from K in the limit for any K∈ℒ.

    p. 10

  • Two streams (sequences) of strings x1:n,x1:n′∈𝒳n (for n∈ℕ∪{∞}) are neighboring if they differ at exactly one timestep. Fix an ε>0. A (randomized) algorithm 𝔾n:𝒳n→Δ(𝒳)n that outputs a distribution Δ(𝒳)i after observing x1:i (i∈[n]) is ε-DP if for all neighboring streams x1:n and x1:n′ and all measurable events ℰ⊆Δ(𝒳)n, Pr⁡[𝔾n(x1:n)∈ℰ]≤eε⋅Pr⁡[𝔾n(x1:n′)∈ℰ].

    p. 12

Theorem 1.3 corrected Private uniform generation sample lower bound

In the paper Theorem 1.3, p. 5, p. 30

For any k,d∈ℕ, there is a finite collection ℒ of size k with closure dimension d such that if the time step n⋆ after which an ε-DP generation algorithm in the continual release model uniformly generates from ℒ satisfies n⋆≤m with probability at least 2/3 independent of the target language and its enumeration, then m=d+Ω(k/ε). Moreover, in the absence of privacy constraints, there is an algorithm that generates after observing d+1 elements from the adversary.

There exists a collection of k languages ℒ={L1,…,Lk} such that for any ε-DP generation algorithm 𝔾 in the continual release model (Definition 5), if the random time n⋆ such that 𝔾 generates from step n⋆ onward satisfies Pr⁡n⋆[n⋆≤m]≥2/3, then m≥1ε(klog⁡2−O(log⁡k)). Theorem 1.5 Private online identification barrier

In the paper Theorem 1.5, p. 5

If ℒ contains two distinct Li,Lj such that |Li∩Lj|=∞,|Li\Lj|<∞, then no ε-DP continual release algorithm (for any ε>0) can identify ℒ in the limit.

Theorem 1.6 Stochastic private identification characterization

In the paper Theorem 1.6, p. 6

A countable collection of languages ℒ is privately identifiable in the limit under stochastic inputs if and only if it satisfies Angluin’s condition.

Terms from the paper (2)

  • An adversary chooses an unknown target language K∈ℒ and a distribution D supported on K.     For all j≥1, if Lj⊇Ti, then Lj is not a proper subset of Li.
