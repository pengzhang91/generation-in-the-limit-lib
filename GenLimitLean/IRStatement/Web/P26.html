How to read the IR statements
  • “Let …” introduces an object, and “Suppose that …” adds an assumption. Both stay in force to the end of the text, or of the bullet they are in.
  • “There is T ∈ ℕ, depending only on …, with the following property.” chooses T, and the rest of the text is the property; when the property is a list, it reads “with the following properties:”. Lean checks the list of dependencies. The list is shown only when the property opens with a new variable (“Let …” or “for every …”), so that the reader sees that T does not depend on it. Otherwise T may depend on everything above, and the list is left out.
  • “All of the following hold:”, “The following are equivalent:” and “At least one of the following holds:” are followed by bullets.
  • A word in italics is the label of a Lean constant, made from its name; point at it to see the constant. A label with one argument reads “X is label”, otherwise label(X, Y, …) with Lean's argument order. Some labels read as a short sentence instead, such as “𝒢 achieves time vector t on 𝒞”; the label's definition in the glossary uses the same sentence. Its negation reads “X is not label …” when the sentence has “is”, and again takes no quantifier after it.
  • “Let K = …” names a term that occurs several times. (x, y) is a pair, [x, y] a list, and () the only element of the one-point type. {0, …, k − 1} is Lean's Fin k. ⟨x⟩ is x as an element of a subtype, such as C(z) in the range of C; Lean supplies the proof of membership. “A member of S” is an element of the set S as a type, and “the set F” is a finite set F used as a set.
  • “Let t ≥ T.”, “for every t ≥ T”, “for every i < n” and “there is i < n such that” range over natural numbers.
  • A proof passed to a label is not shown when Lean can prove it from the assumptions. “label(X, Y) does not hold” and A ⊈ B are negations; no quantifier follows “does not hold”. Many names follow the paper (𝒞, ℋ, t⋆, …), to make reading the two side by side easier; each statement still says what its names stand for.
  • A statement that begins with “Setting A.” begins with the sentences of Setting A, listed under “Throughout”. The checker puts them in place of the mark.
  • A label with a dotted underline links to its definition in the glossary at the end of the page. A definition reads “By definition, … if and only if …”; Lean proves it by Iff.rfl, so it is the label's definition, unfolded once.
  • {x(n) : n < t} is the set of the first t terms of x, and ∖ is set difference. “O has a membership oracle” means that O comes with a correct test for x ∈ Li.

The paper’s setting (4)

  • Let L be a countable class of languages over a finite alphabet Σ. An infinite sequence of strings E = (x1, x2, . . .) is an enumeration of a language K ∈ L if the set {xt}t∈N is equal to K. The class L is identifiable in the limit if there exists an algorithm I that, for any K ∈ L and any enumeration E of K, converges to a correct representation of K. That is, there exists a time t∗ such that for all t ≥ t∗, the algorithm’s guess It(x1, . . . , xt) is constant and correct.

    p. 3

  • Let L be a class of languages and M be a class of machines. For a machine M ∈ M and an input x ∈ L(M), let cM(x) be the accepting sequence of computational steps of M on x. An enumeration of K with traces from M is a sequence Etrace = ((x1, cM(x1)), (x2, cM(x2)), . . .) where (xt) is an enumeration of K = L(M). The class L is identifiable in the limit with traces from M if there exists an algorithm I that converges to a correct representation of K when given any such Etrace.

    p. 4

  • it is a corrupted version of the true trace cM(xt) with edit distance error eM(xt)

    p. 5

  • For all the results of this paper, we assume the algorithm knows which error regime it operates in. Moreover, for the constant error rate regime, the constant α and ℓα are known in advance; for the diminishing error rate regime, (α, ℓα) are known for all α ∈ (0, 1), while for the finite error, the algorithm knows the constant C and ℓC.

    p. 6

Theorem 3.1 Turing identification from perfect traces

In the paper Theorem 3.1, p. 6

Let M be the collection of all TMs and L = {L1, L2, . . .} where every L ∈ L is recognized by some M ∈ M. Then, L is identifiable in the limit with trace from M.

Terms from the paper (2)

  • At every timestep of its execution, every computational machine we are considering can be described by a set of parameters (e.g., its current state, memory tape, position on the tape etc.). A computational trace simply describes the set of (changing) parameters of the underlying machine in every timestep. Thus, the length of the trace is the number of computational steps the machine needs to accept the given string.

    p. 4

  • A Turing Machine (TM) is a 7-tuple (Q, Σ, Γ, δ, q0, B, F) that includes a set of states Q, an input alphabet Σ, a tape alphabet Γ ⊇ Σ, the initial state q0, a blank symbol B ∈ Γ \ Σ, a set of accepting states F ⊆ Q and a transition function δ : Q × Γ → Q × Γ × {L, R}.

    p. 4

Theorem 4.1 Finite automata tolerate a constant edit rate

In the paper Theorem 4.1, p. 7

For the task of robust identification in the limit with the set of machines as DFAs, there is a robust identification algorithm that guarantees to succeed in the constant error rate regime.

Terms from the paper (2)

  • Constant error rate: There is a fixed constant α ∈ (0, 1), such that the edit distance error rate is bounded by α asymptotically. Formally, there exists a pair of constants α, ℓα such that for any input string x with length at least ℓα (|x| ≥ ℓα), its corruption error is at most an α-fraction of actual computation trace, i.e., eM(x)/|cM(x)| ≤ α.

    p. 5

  • if Q is the set of states of the machine, the corrupted trace does not introduce states that are not in Q.

Theorem 4.3 Diminishing versus constant error for pushdown machines

In the paper Theorem 4.3, p. 8

Consider the task of robust language identification in the limit with the set machines as DPDAs, then • There is an algorithm that guarantees to succeed in the diminishing error rate regime; • Robust language identification is impossible in the constant error rate regime, for any constant α > 0.

Terms from the paper (3)

  • Diminishing error rate: The edit distance error rate is o(1) asymptotically. Formally, for any constant α ∈ (0, 1) there exists a constant ℓα (depending on the value of α) such that for any input string x of length at least ℓα (|x| ≥ ℓα), the corruption error is at most an α-fraction of the actual computation trace, i.e., eM(x)/|cM(x)| ≤ α.

    p. 5

  • Constant error rate: There is a fixed constant α ∈ (0, 1), such that the edit distance error rate is bounded by α asymptotically.     p. 5

  • Throughout Section 4.2, we assume DPDAs are in a normal form where each transition (1) reads either one input symbol or ϵ, and (2) modifies the stack by at most one symbol (push or pop one symbol). We also assume acceptance by empty stack.

Theorem 4.5 Bounded versus diminishing error for Turing machines

In the paper Theorem 4.5, p. 9

Consider the task of robust language identification in the limit with the set machines as Turing machines, then • There is an algorithm that guarantees to succeed when the number of errors is finite; • Robust language identification is impossible even in the diminishing error regime.

Terms from the paper (3)

  • Finite error: The edit distance is bounded by an absolute constant C asymptotically. Formally, there exists a constant length ℓC such that for any input string x of length at least ℓC (|x| ≥ ℓC), the edit distance error is bounded by C, i.e., eM(x) ≤ C.

    p. 6

  • Diminishing error rate: The edit distance error rate is o(1) asymptotically. Formally, for any constant α ∈ (0, 1) there exists a constant ℓα (depending on the value of α) such that for any input string x of length at least ℓα (|x| ≥ ℓα), the corruption error is at most an α-fraction of the actual computation trace, i.e., eM(x)/|cM(x)| ≤ α.

    p. 5

  • We assume the alphabet for both input string and the writing tape are binary. We assume Turing machine has an input tape (read-only) and one write-tape, our results extend to multiple write-tapes easily.

    p. 16
