# Focused computational-scope review: Theorems 3.1, 3.3, 3.5

The Lean interfaces establish semantic existence and explicit conditional computation claims. They do not establish all the unconditional ordinary-computation claims one might read into the paper's word “algorithm.” The paper, however, expressly grants oracle access and does not consistently specify when “computable” means ordinary or oracle-relative. Accordingly, the differences cannot responsibly be classified by one blanket stronger/weaker verdict.

This independent supplement used only the pinned Stage 2 inputs, the frozen code-only reconstruction (SHA-256 `ac42c709b4ca0a380a9c8279260d4f1bed7e59871c1f14962ee238b00fca5d9a`), and supplied page images. Lean evidence below is exported types and definition values, never comments or theorem proof bodies. No Lean proofs were written, changed, or checked. Source proof text is used to interpret conventions, not to audit proof correspondence. All PDF numbers below are one-based. `P3/` abbreviates `GenLimitLean/GenLimit/Paper03_HallucinationAndModeCollapse/` in the frozen snapshot.

## Source conventions: literal text and interpretation

* **Computation is part of the source model.** Section 1.1.1, printed p. 4 / PDF 7, describes computable maps from data to sampling Turing machines. Section 3.1.1, printed p. 25 / PDF 28, expressly calls the learners computable. A bare probability kernel is therefore not automatically a full translation of an algorithm in this model.
* **The standing language oracle is uniform as an oracle.** Printed p. 21 / PDF 24 grants one membership oracle taking both an index and a string. This matches the arity and truth specification of `OracleFamily.query`. It does not explicitly assert that this two-argument oracle is ordinarily computable. The motivation mentions grammars and Turing-decidable languages, and says each language admits an oracle; that motivation does not itself provide an ordinary uniform procedure on arbitrary family indices.
* **Tell-tales come with an additional oracle in the source.** Definition 11, printed p. 22 / PDF 25, posits an oracle enumerating `T_i` from `i`, and the following paragraph stresses access to that procedure. The literal phrase is “set of finite strings,” which by itself does not assert finite cardinality. The intended finite-tell-tale reading is supported explicitly in Appendix B.1, printed pp. 91-92 / PDF 94-95. The source does not specify here whether the tell-tale oracle must be ordinary computable, computable relative to membership, or an independent arbitrary oracle. These readings must be kept separate.
* **MOP is literally pointwise in training data.** Definition 6, printed p. 5 / PDF 8, quantifies over each sample size and dataset and asks decidability for the resulting generator. This matches Lean's `forall xs, exists decider`. Definition 5, printed pp. 5 and 28 / PDF 8 and 31, mentions a generator description as input, which can suggest a uniform reading, but Definition 6 does not state an effective selection operation over histories. Printed p. 28 / PDF 31 stresses existence of the decider rather than user access to it. Later, the proof of 3.5 uses changing trained generators as MOP subroutines and asserts a Turing-machine implementation (printed pp. 62-63 / PDF 65-66). That implementation assertion requires uniform access or an additional argument; pointwise existence alone does not supply it. This is a source uniformity ambiguity, not grounds to silently replace Definition 6 by a stronger definition.
* **The sampling proof mixes these levels.** Proposition 6.5, printed p. 61 / PDF 64, describes sampling using membership queries and calls membership in the selected language decidable. The proof of 3.3 then composes identification with this sampler (printed pp. 61-62 / PDF 64-65). This supports an oracle-relative algorithmic reading, or an intended restriction to recursive languages. It does not establish ordinary uniform membership or ordinary effective selection of tell-tales for every indexed family.

## What the Lean types actually say

`IdentifiableInLimit` (`P3/Definitions.lean:104`) is `SemanticallyInferrable`: an arbitrary function from finite histories to indices eventually stabilizes to an index denoting the target. Its expansion is in `Paper00A_PositiveDataInference/Semantic/Definitions.lean:24,30` and `Core/Identification.lean:18,47,53`. No ordinary or relative computability condition is included. `ConditionTwo` (`Paper00A_PositiveDataInference/Semantic/Definitions.lean:52`) is `forall i, exists T : Finset Nat, IsTellTale C i T`. The tell-tale subset condition at line 39 matches the intended finite combinatorial condition in Definition 11. Selection of finite sets does not assert a computable enumeration from the index.

`OracleFamily` (`Core/OracleFamily.lean:17-21`) has an indexed family of infinite languages and one correct Boolean membership query, with no computability certificate. The conditions `Computable₂ O.query` in the targets mean one ordinary procedure jointly in index and string. They are stronger than individual ordinary decidability of each language and are explicit sufficient specializations, not a hidden property of `OracleFamily`.

`DecidableMOP` (`P3/BreadthModel.lean:41`) is `forall xs, exists query, Computable query and correct_support_test xs query`. `UniformDecidableMOP` (line 45) instead requires a single `Computable₂` support test on history and string. `OracleMOP` (`P3/SupportMembership.lean:23`) is also pointwise: each fixed history has some truth-table program deciding its support relative to the supplied oracle. Its program need not be selected effectively from history. Truth-table programs (`Support/OracleTruthTable.lean:14,20`) are a particular finite-query relative-computation model; they should not be equated by definition with unrestricted oracle computation or ordinary decidability.

`HasComputableSampler` (`P3/SupportMembership.lean:27`) asserts one ordinary computable function of `(history, seed)` whose pushforward of the fixed positive geometric seed law equals the output PMF. This is a genuine uniform sampler certificate. It is separate from either MOP property. `StatisticalGenerator` and `StatisticalIdentifier` themselves are unrestricted maps from histories to PMFs (`P3/GenerationModel.lean:17`; `P3/StatisticalModel.lean:33`). These definitions require neither a sampling machine nor computable probabilities.

The positive breadth definitions choose an arbitrary `emit : Nat -> Nat -> Option Nat`, with a finite tell-tale as each emitted range. Existence of this `emit` is non-effective selection/encoding of the tell-tales, not an assertion of `Computable₂ emit`. The named learner runs a truth-table program against `identificationOracle`, which explicitly combines membership answers and `emit` answers (`P3/OracleIdentification.lean:111`; `P3/StatisticalBreadth.lean:23`). The sampling definitions use an oracle-search procedure and a geometric seed (`P3/ExactSampler.lean:62,78,88,111`). Thus these definitions expose relative procedures using the two chosen oracles; their ordinary computation guarantees must still be read with their displayed hypotheses. No target supplies a uniform transformation on finite descriptions of arbitrary families.

## Adjudication of the three targets

**3.1** (`P3/Results/Overview.lean:60`; source printed p. 27 / PDF 30). The positive predicate `AlmostExponentialIdentifiable` (`P3/UniversalRates.lean:39`) chooses arbitrary deterministic learners, with no computation certificate, and the characterization uses semantic `ConditionTwo`. The finite combinatorial content faithfully represents the intended finite-tell-tale condition if the source's tell-tale oracle may be arbitrary. If Definition 11 means an effective enumeration, Lean omits that requirement. Likewise, the positive interface omits the source's algorithmic implementation guarantee unless “learner” is intentionally being read semantically or a separate bridge to computation relative to the allowed oracles is supplied. Source Lemma 5.5 uses the online learner and membership-based postprocessing (printed pp. 40-43 / PDF 43-46); it does not justify erasing the distinction. Conversely, Lean's negative rate quantifiers range over arbitrary PMF-valued learners, while semantic non-identifiability can cover fewer families than non-identifiability in a restricted computational model. The changes oppose each other; there is no single global stronger/weaker classification.

**3.3** (`P3/Results/Overview.lean:104`; source printed p. 30 / PDF 33). The negative MOP premise matches Definition 6's pointwise wording, but non-identifiability remains semantic and the quantified generators are arbitrary kernels. For the non-breadth existence claim, Lean gives pointwise ordinary MOP unconditionally and an ordinary sampler only if `Computable₂ O.query`. The deterministic point-mass nature explains why pointwise MOP does not by itself certify that training/output selection is computable.

For the positive breadth claim, `CertifiedBreadthPositiveBranch` (`P3/StatisticalBreadth.lean:32`) supplies the chosen tell-tale enumeration, oracle MOP, and **exponential** breadth for one fixed named generator (hence also all the admissible almost-exponential rates). Ordinary pointwise MOP is conditional on `Computable₂ O.query`; an ordinary sampler and uniform MOP are conditional on **both** `Computable₂ O.query` and `Computable₂ emit`. The exponential rate component exceeds the stated almost-exponential positive conclusion, whereas the ordinary algorithm/MOP guarantees are conditional. It is faithful as an oracle-relative construction if both chosen oracles are allowed and MOP is read relative to membership. It is a safe ordinary-computational specialization when the two displayed computation hypotheses hold. It is not an unconditional ordinary-computational realization for every semantically identifiable `OracleFamily`. Individual recursive languages could suffice for pointwise ordinary MOP, but this interface does not state that weaker sufficient assumption.

**3.5** (`P3/Results/Overview.lean:129`; source printed p. 31 / PDF 34, restated p. 62 / PDF 65). `CertifiedOnlineBreadthPositiveBranch` (`P3/OnlineBreadthConstruction.lean:90`) has the same oracle/ordinary distinction and gives both fresh and repeating breadth. Repeating versus fresh breadth is an explicit source-sanctioned variation (Remark 2, printed p. 29 / PDF 32). Unconditionally the branch gives oracle MOP. Ordinary pointwise MOP needs uniform ordinary family membership; the ordinary sampler and uniform MOP additionally need ordinary computable `emit`. The displayed iff clauses also require `Computable₂ O.query`, and their generator witnesses are still arbitrary kernels with pointwise MOP. That hypothesis alone does not turn the chosen semantic learner or `emit` into an ordinary algorithm. The positive claim is faithful under the same relative interpretation as above, or under the effective specializations; as a claim about ordinary sampling algorithms with only semantic identification assumed, an implementation guarantee remains omitted from the interface. The proof section spells out the negative reduction and does not independently resolve this positive computational convention.

## Informal model separations and limits

The following are mathematical checks, **not Lean-checked claims**, not counterexamples to the compiled theorems, and not alleged counterexamples to the paper under its intended oracle/recursive conventions.

1. **Pointwise MOP does not imply uniform MOP, even with a joint computable sampler.** On history `[e]`, sample a geometric natural seed. Every even seed outputs 0; seed `2k+1` outputs 1 exactly when machine `e` halts within `k` steps, otherwise 0. This is a total computable seed sampler. Every fixed support is either `{0}` or `{0,1}`, hence ordinarily decidable. A uniform support test at 1 would decide halting. This validates the distinction in Definition 6 and prevents replacing its pointwise premise without evidence.
2. **Individual membership and tell-tale selection need not be uniform/effective.** Let `A` be an infinite coinfinite non-c.e. set and `E` the evens. Put `C_i = E union {2i+1}` when `i in A`, and `C_i = E` otherwise. Every individual language is recursive and infinite; every index has a finite tell-tale (the exceptional odd element, or the empty set). Uniform ordinary membership would decide `A`. A computable tell-tale emitter would enumerate `A`, because every augmented language has `E` as a proper family sublanguage and therefore its tell-tale must contain its unique odd element. Neither uniform ordinary guarantee follows. This example separates assumptions; it does not claim that this family lacks an ordinary identifier, nor that a membership-relative emitter is impossible.
3. **Arbitrary oracles cannot silently become ordinary samplers.** Choose infinite non-c.e. `B`, and let `K = {0} union {2n+2 : n in B}` and `L = {0} union {2n+1 : n in Nat}`. These two infinite incomparable languages have finite tell-tales and intersection `{0}`, so they meet the semantic identification and finite-intersection nontriviality conditions. Exact fresh support on `K` is non-c.e. after removing any finite history. An ordinary sampling Turing machine has c.e. support (enumerate finite output-producing random-bit computations), so no ordinary sampler can realize that support. Membership-oracle-relative sampling can. This supports retaining Lean's computation hypotheses and the source's oracle/recursive qualification; it does not settle which qualification the paper intends in every occurrence of “algorithm.”

The open adjudication points are the allowed computational power of the source's two oracles, whether its computability conventions are consistently relativized, and whether its MOP reductions intend a uniform decider despite Definition 6's pointwise form. None is resolved merely by renaming a Lean predicate. The signatures establish the conditional guarantees above; a faithful computational comparison must state the chosen source interpretation explicitly.
