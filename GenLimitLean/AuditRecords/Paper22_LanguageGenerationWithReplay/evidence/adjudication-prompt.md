# Stage 3 — adjudicate discrepancies and documented source corrections

Read the frozen Stage 1/2 outputs, exact source and Lean snapshot. Developer comments, PaperMap, registry notes, correction records and relevant historical reviews are now allowed as fallible explanations. Pin their actual versions/hashes. Do not rewrite frozen reports. Disclose whether you are a fresh reviewer, a continuing Stage 2 reviewer or a coordinator with prior context; disclose any parent-supplied argument. Do not claim independence that did not occur.

For each material discrepancy, and every scoped target in the final coverage table:

1. Restate the Stage 2 finding and the exact source and Lean claims. Include global assumptions and necessary definitions; distinguish a literal formula from a proposed repaired reading.
2. Inventory pre-existing explanations with source anchors and hashes. A comment can establish that a choice was disclosed, but cannot establish mathematical truth, computability or equivalence. Check the actual defining expressions and any relevant explicit theorem interfaces.
3. Test the explanation mathematically. For a suspected source error, give the smallest argument or counterexample you can justify, checking every premise: domain/family, nontriviality, nonidentifiability, infinitude, computation/oracle access, stability, MOP, distribution validity, all sample sizes and probability quantifiers as applicable. Mark informal arguments as not Lean-checked. Finite experiments do not prove infinite claims. Do not infer correctness of all paper proofs or all Lean proofs from a local argument.
4. Specify the smallest source repair and check whether Lean implements it. A source sign correction must not silently excuse a separate changed hypothesis or missing computational guarantee. If evidence is only suggestive, retain uncertainty.
5. Resolve separately: (a) source correspondence; (b) mathematical evidence and its validation level; (c) final disposition: matches source context, justified source correction, qualified model/representation choice, substantive formalization/coverage gap, or unresolved. Split mixed components. Keep literal non-equivalence visible even when the correction is accepted.
6. Give minimal follow-up actions without making unrequested source changes. Existing documentation should prevent reporting a disclosed valid correction as an unexplained Lean error; it should not turn an unsupported explanation into a pass.

Computation: explicitly compare the source's permitted oracles with the formal ones. Distinguish semantic learners, finite-query relative procedures, ordinary computation, per-history deciders and uniform selectors, and ordinary samplers. Separate ordinary sufficient hypotheses from claims that those hypotheses are necessary. If a construction lives outside the requested target facade, record its exact interface as supporting context; do not silently expand scope or treat imports as proof of a missing target guarantee.

Output `adjudication.md` with an executive disposition, one row for every target, discrepancy dossiers, existing-explanation inventory, mathematical checks, validation limits and remaining work. Output `adjudication-run.json` with actual input hashes, allowed-context boundary, reviewer/model/configuration provenance, original frozen output hashes, revised dispositions and output hash. Completion status is separate from verdict. Update only the coordinator's summary/aggregate metadata and result checksum manifest as authorized, preserving all frozen evidence and no-Git policies.
