## Discrepancy dossiers and mathematical checks

Each check below is explicitly **informal and not Lean-checked**. Existing exported theorem types are evidence of stated conclusions, not proof certification.

### M1 — Criticality definitions differ, without refuting a v1 headline theorem

Let L1=N+\{2}, L2=N+\{3}, L3=N+\{2,4}, and extend the indexed family by repeating L1. All are infinite decidable sets. A legal history containing only 1 keeps all three consistent. Under all-consistent criticality only L1 is critical: L2 contains 2 missing from L1, and L3 contains 3 missing from L2. With a fixed scope including the first three, announcing 3 (legal for target L1) falsifies L2 while L1 survives; L3 then becomes all-consistent critical. Under recursive criticality L3 was already critical because L2 was noncritical and L3⊆L1. Thus the definitions/foci differ on legal infinite-family prefixes. Such prefixes extend to full target presentations; this is not a finite experiment used to prove an infinite performance claim.

Smallest source/documentation repair: Keep editions separate. A generic literal-v1 correctness theorem needs a v1 machine interface and its own proof, or an explicit source revision to recursive criticality.

Does Lean implement it? The existing machine implements the recursive earlier/v2 definition, not a literal-v1 algorithm. No equivalence of the generic machines follows.

### M2 — Distinct labels suffice for the logarithmic conclusion

Fix an ambient cutoff n and let m be the finite number of loss values below n. If m=0, the claimed bound is immediate, including target count 0. Otherwise, positive injective integer labels on those m losses include a label tau≥m. Its charge has at least 2^tau≥2^m distinct elements; charge support lies in the target and below that loss, hence below n. Thus the target count N below n satisfies N≥2^m, so m≤floor(log2 N). No charge disjointness is used. The actual certificate constructor explicitly supplies every premise, and a native theorem has this precise conclusion.

Smallest source/documentation repair: No source-statement repair is necessary. Describe this as an alternative sufficient charging argument and preserve the deliberate settled cutoff; do not claim the source proof’s disjoint-charge assertion was formalized.

Does Lean implement it? Yes at the explicit certificate/statement interface. The certificate is instantiated for the named settled machine; the Lean proof body is not reviewed.

### M3 — The increasing counterexample and its version-limited transfer

For L1=positive odds∪positive multiples of 4 and every later even tail, every later candidate contains some value congruent to 2 mod 4 and therefore is not a subset of L1. Since the stream 4(t+1) stays in L1, L1 is the only critical language under either criticality definition, so the intended focus is fixed. After t previous rounds the used generator values are 1,3,...,2t−1. The next odd 2t+1 is fresh; every multiple of 4 below it has already appeared among 4,8,...,4(t+1), and any unannounced such multiple is larger. Therefore the next least fresh focus value is 2t+1. All outputs lie outside K=positive evens, giving failed target validity and zero target-owned coverage. For arbitrary reordered multiples of 4, the all-odd assertion is not justified by this argument.

Smallest source/documentation repair: State the increasing order explicitly, as v2 does, or formulate earlier/v1 as existence of a bad presentation. Distinguish generic value shifting from this unchanged-positive-value example.

Does Lean implement it? The explicit increasing recursive example is implemented and has the stated native bundle. There is no formal all-consistent-machine definition/theorem, so the informal v1 transfer earns no literal-v1 formalization credit.

### M4 — A concrete candidate for repairing the v1 partial-closure proof step

Let K=L_z and infinite E⊆K be exactly enumerated. After a finite time, each original L_i with i≤z is consistent iff E⊆L_i: a non-superset is eventually falsified by one of finitely many needed E-witnesses. Let I={i≤z:E⊆L_i}; it contains z. The finite intersection H=⋂_{i∈I}L_i contains E, is infinite, and is a subset of K, with a nonzero binary code whose highest bit is z. Every earlier consistent binary-coded intersection uses only indices ≤z; after the chosen time, each of its constituent indices lies in I. Hence H is contained in every such earlier consistent intersection and is itself consistent. H is therefore permanently all-consistent critical. Discarding finite intersections preserves H and the earlier-code order.

Smallest source/documentation repair: Insert a full closure-aware justification of this candidate and then justify the v1 machine’s scope/validity dynamics. Containment in one last critical language alone is not the full all-consistent condition.

Does Lean implement it? Lean uses recursive criticality; its existing permanent-subset theorem is related but does not implement a literal all-consistent-machine proof. The v1 statement is not refuted here, and its formalization gap remains.
