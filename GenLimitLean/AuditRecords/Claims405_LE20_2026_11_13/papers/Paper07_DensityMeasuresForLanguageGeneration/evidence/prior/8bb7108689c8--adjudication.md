## Charging: the paper, the interfaces and the unsupported inference

Stage 2 found that Lemma 6.16, p.46/PDF48, needs an injective map from retained long-bad inputs to earlier-in-time, smaller outputs. The p.48-51/PDF50-53 argument constructs Phi into unordered charged pairs and finishes by selecting an output rho. PaperMap lines 102-105 says overlapping distinct pairs “supplies only a capacity-two charge”; its table and registry similarly describe that as the charge justified by the source construction.

The parent-supplied objection is correct: pairs {10,20}, {10,30}, {10,40} are distinct, yet choosing 10 from each produces multiplicity three. Adding more pairs makes multiplicity arbitrarily large. This disproves the abstract pair-injection-to-capacity-two inference. It is not a counterexample to the full paper algorithm, whose timing, critical-language and bad-interval constraints must also be checked.

The actual source queue rules do give useful pointwise information. Conditionally on the previously claimed theta/F/pair construction and the late K-valid phase, an eligible pair is charged before its bad input. If its values precede that input and one is still available at the deadline, priority would force a small current output, contradicting badness. At the first consumption of the pair, either an output consumes a token, or an input consumes one while the other is still available and bounds that round's output. If the bad key precedes both tokens, the key itself would have been queued and would force a small previous output, again contradicting badness. These arguments explain the proposed earlier/smaller output for each retained input. They do not, by themselves, bound how many different pairs choose the same output.

The complete native interfaces establish an additional, precise sufficient route. FirstConsumptionBridge.TokenSource.mk requires global injectivity of (demand,side)->token string. Schedule.mk requires freshness at reservation, consumption before each deadline, injective output positions, correspondence between token and output positions, priority inequalities, tokens no larger than keys, and keys absent from outputs. Schedule.charge chooses the output position at the earlier of the two tokens' first-use rounds. Its two injection theorems separate demands where that first-use token is consumed by the input from those consumed by the output.

The reason for each separate injection can be checked informally: equal output positions give equal rounds; in the input-first class both demands then name the same round's input token, and in the output-first class both name its output token. Global token uniqueness identifies the demand. Each class therefore has at most one preimage, giving total capacity at most two. These exact pre-existing theorem interfaces support that sufficient result; I did not audit their proof steps.

Even globally disjoint pairs do not force global injection across classes. A local priority-compatible fragment can consume input 5 and output 6 in one round, with pair A={5,10} input-first and pair B={6,7} output-first, their other tokens consumed later. Both charge output 6; priority output 6<=10 is respected. This informal fragment tests the scheduling inference only, not a complete P07 bad-run realization. The native Schedule.charge_injective correctly asks for the additional NoCrossCollision predicate.

The source lacks the native global reservation-freshness discipline: it adds unused strings to a set-valued queue, so the same still-unused string may be included at multiple events. Distinct pair labels are weaker than globally distinct token strings. I have not established that its additional criticality, theta/F minimality and maximal-bad-run conditions imply global token uniqueness, per-class injection or any uniform multiplicity bound. Conversely, I have not built a full source execution violating those bounds. Thus the correct adjudication is unresolved realization, plus a demonstrably invalid abstract explanation. The smallest documentary repair is “conditional capacity-two endgame under separately injective charge classes,” retaining the independent conditional 1/8 route. Merely replacing 1/8 by 1/10 in the source theorem is not justified.

## The ancestry diagnostic versus the actual late source regime

PaperMap lines 76-77 and the registry's 6.11 card say the printed cross-round persistence premise is refuted. The existing native counterexample does establish unrestricted ancestry loss despite consistency, even with every language infinite. Its precise premises limit what that means.

Direct definitions are: original top=Nat, blocker={0,1}, even language=even naturals, child={0,2}; pad(A)=all evens union {2a+1:a in A}. Padded family indices 0,1,2,3 are these four languages. The stream begins 1,5, then enumerates all evens, presenting padded child. The rank-two theorem compares child representatives at rounds 0 and 1: the child first has padded top as ancestor, then loses it, while top remains consistent. Parent candidate sets change from {0} to {0,2}.

This respects source infinitude, but fails the source proof's stable-phase and actual-selection premises. At the old round the observed prefix is {1}; the earlier blocker contains 1 but not the child's element 5. Hence the child is not strictly critical then. The same blocker obstructs it even before observations. These child representatives therefore are not the corresponding A_acc selected points. More explicitly, the second selector step uses the previous prefix {1} and new input 5: blocker index 1 is the first bad strictly critical language, so the boundary selects top index 0, rather than child. These are informal consequences of the exported definitions, not new Lean proofs.

Also the compared rounds precede the target index z=3 and the cutoff assumptions used in the late ancestry argument. The counterexample type contains no actual fallback trace, output state or bad-run hypothesis. It refutes the unrestricted forest persistence assertion; it does not refute eventual Claim 6.11, the finite density theorem or the needed inference with all late-run premises restored. “The printed proof needs a justified cross-round step” is warranted; “the theorem is false” is not.

FrozenFrame is substantive supporting mathematics. target_ancestor_of_pullback_at_stable_origin and FrozenFrame.exists_strictAdvance_of_target assume stable criticality, origin beyond z, exclusion of same-or-higher-level proper K-subsets, and K-containment of current/later points. They pull both points into one origin forest; an explicit non-ancestry/escape premise then yields a higher-level frame still inside K. They do not show that successive actual bad inputs provide these escape premises, nor the seed/reset procedure or full run-length/count bound. The minimal follow-up is that bridge, or a genuine stable A_acc/bad-run counterexample, not promotion of the early diagnostic to a theorem-level refutation.

## Causal realization and further source qualifications

The native recursive execution is real infrastructure: RecursiveHistory.advance observes input, reserves a finite batch and emits from an updated state; historicalPairFamily and runTokenSource produce provenance and globally unique token sources for its RunDemand. RunThinning, PrefixCharge, TwoTokenCharge and LongBadCharge provide a conditional global-injection 1/8 path. The facade's 1/10 choice does not erase that work.

However RunSpec accepts arbitrary input, current:Nat->FamilyPoint C, infinite reservation languages and finite duplicate-free edge lists. It neither binds these to A_acc and the source's actual fallback gaps nor requires their choices to respect equal finite histories. A recursion driven by a supplied future-dependent schedule is not automatically a causal learner. A source instantiation must prove finite-history dependence, connect retained intervals to demands, obtain deadlines and priority in target positions, and show eventual validity despite queued earlier hallucinations. Ledger allocation additionally forbids all previously reserved strings, including unconsumed ones; that changed discipline can be a legitimate alternative algorithm. Literal trace identity is unnecessary if validity and density are proved anew, but currently neither route is supplied end to end.

No ordinary computability obligation should be invented. The source explicitly allows arbitrary functions, p.7/PDF9, despite presenting a membership black box on p.6/PDF8. Semantic family predicates and classical choice are compatible with that setting. The interfaces prove neither ordinary computability nor uniform finite-query relative procedures; the source does not require them here. Its unordered f_X(St) wording does conflict with the chronological detailed algorithms. The smallest clarification is to allow finite ordered histories/state. Lean matches that detailed mechanism; equivalence to a function of the unordered sample alone remains unproved.

The disclosed StrictCritical repair is justified: comparing to itself by proper inclusion is impossible, while immediately following source prose uses i<n. Claim 3.2's printed i<r proof bound likewise must be i<n. These local normalizations do not establish unrelated theorem proofs. By contrast Claim 6.6's nonempty first language is automatic in the paper's all-infinite domain, p.1/PDF3. Lean's explicit nonempty premise is necessary for its generalized domain including empty sets, not a repair of the source-domain assertion.

For the breadth epsilon issue, the source proof's inference from breadth<=epsilon to infinitely many exact density<=epsilon is not licensed by Definition 4.2. An informal minimal repair preserves the claimed lower-bound statement: to prove breadth>=epsilon, assume breadth b<epsilon, choose an admissible beta between b and epsilon and positive slack smaller than epsilon-beta. The definition then supplies infinitely many densities strictly below epsilon; their tower would contradict absence of an epsilon-thin tower. This repairs the endpoint reasoning, conditional on the remaining extraction argument, and is not a new Lean characterization proof.

PaperMap line 69 and the registry overlook a different quantifier issue. Displayed Theorem 5.1, p.25/PDF27, says exists A forall c<1, upper density>=c/2; the overview/proof use forall c exists A. The parameter change alone is equivalent only under the latter order. The smallest repair is to move the parameter quantifier outside algorithm existence, matching the proof and Theorem 2.5. A single algorithm achieving every c would require a separate construction. No native Section 5 algorithm establishes either version. Truth-index existence/minimax directions and thin-tower adversarial forcing likewise remain missing mathematics, not consequences of conditional uniqueness or count lemmas.
