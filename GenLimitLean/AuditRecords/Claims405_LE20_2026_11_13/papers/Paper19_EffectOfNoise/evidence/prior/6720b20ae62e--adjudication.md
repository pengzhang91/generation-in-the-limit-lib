## Algorithm 1: exact transitions fail; conservative validity survives

The source at printed p13/PDF14 adds candidate block `a_i` iff it is disjoint from previously forbidden output columns and its own output is outside the current language. Native block `B_i` is `{(i,k) | k<i+1}` (`Separation:207`); its prefix has one first point from each column (`:245`). `algorithmForbidden` (`:577-585`) includes chosen indices, the **first coordinates of all prior output columns**, and all indices whose outputs hit a previously selected block. `algorithmScanStep` (`RejectedScan:68`) accepts precisely outside that finite forbidden set. `algorithmRejectedScan:97` advances once per increasingly enumerated outside candidate, retaining rejection positions.

The first-coordinate test is sufficient but not necessary for disjointness: an output column `(j,k)` with `k>=j+1` is outside `B_j`, yet still forbids index `j`. No opened explanation supplies a missing invariant ruling this out.

A total semantic generator gives a counterexample satisfying every relevant branch premise:

```text
G(n, xs) = ((n, n+2), 0).
```

The internal universe is `(Nat x Nat) x Nat`, exactly `ColumnPoint`; this function ignores the history and has the required generator type, without oracles. At prefix `i` of length `i+1`, its output column is `(i+1,i+3)`. For every block `j`, membership would require `j=i+1` and `i+3<j+1=i+2`, which is impossible. Consequently the outside-index set is **all naturals, hence infinite**, and every `indicesHittingBlock G j` is empty, hence finite. This is a global argument, not extrapolation from a finite experiment. All column-union languages under discussion remain infinite because each selected column contains a copy of `Nat`.

At the first scan candidate, both rules select block 0. The old output column is `(1,3)`. At candidate 1, the source's literal test applied to these native blocks accepts: `B_1={(1,0),(1,1)}` misses `(1,3)`, and the new output column `(2,4)` misses the selected block 0. Native forbidden indices are `{0,1}`, so it rejects candidate 1. The selected states after two attempts are `{0,1}` versus `{0}`. The source's original consecutive integer blocks and native tagged blocks are already different representations; even granting that disclosed representation change, the acceptance predicates disagree. A bijective renaming of points does not turn nonmembership into membership. This is not merely compression of rejected iterations.

The stronger test nevertheless gives a valid alternative construction, informally. For finite chosen set `A`, its forbidden set is finite under the finite-hit premise. Acceptance guarantees both directions of conflict freedom: avoiding previous output first coordinates prevents an old output from entering the new block; avoiding incoming hit indices prevents the new output from entering an old block; outside-candidate membership handles its own block. Suppose the increasing scan selected only finitely many indices in total. Its monotone finite states would eventually stabilize at that finite set. Infinitely many outside candidates remain, while its forbidden set is finite, so some later candidate would be accepted, a contradiction. Thus infinitely many blocks are selected and every selected output stays outside their column union.

That union is a valid nonempty infinite-language target. Selected prefixes lie in it and have unbounded lengths. Each finite injective prefix extends to an exhaustive injective enumeration of this target, as the supplied prefix-completion interface states. For any proposed targetwise threshold, a sufficiently long selected prefix gives a membership error. The stream may depend on the threshold, which is exactly enough to refute nonuniform generation. This mathematical check validates the alternative construction's intended separation argument without auditing Lean proof steps.

Disposition: retain the theorem correspondence, accept a conservative semantic construction variant, and reject the documentation's exact-transition claim. The smallest documentation repair is to say that rejected iterations are retained **for the stronger native test**, remove the claimed equivalence at `RejectedScan:64`, and describe the alternative conflict-free construction. If literal Algorithm 1 is required, the exclusion term must test actual output-column membership in the candidate block; that is an implementation change requiring its own verification, not performed here. No source repair is needed to justify the existing paper algorithm.
