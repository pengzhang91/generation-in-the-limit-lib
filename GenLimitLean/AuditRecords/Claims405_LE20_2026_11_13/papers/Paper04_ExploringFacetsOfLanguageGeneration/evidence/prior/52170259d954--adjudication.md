## Mathematical checks and discrepancy dossiers

### Computation: permitted oracles versus certified interfaces

Stage 2 correctly separated arbitrary functions from ordinary computation, but lack of ordinary computability is not itself a contradiction when the source permits stronger oracles. Source p. 9 grants membership and finite-intersection-finiteness queries. Informally, on an effective string enumeration, each greedy stage makes finitely many sample membership tests and intersection-oracle calls. Its retained intersection is infinite; scanning words until an unseen retained member is found therefore terminates. This validates a finite-query relative implementation of the extensional greedy rule using exactly those resources. It does not make every arbitrary Classical.choose witness equal to the scanning implementation, nor establish a Lean relative-computability certificate. Targets 1/6 remain semantic abstractions of that guarantee.

Proposition 6.2, pp. 22-23, grants finite-difference decisions; Remark 5 explicitly acknowledges subset decisions and discusses eliminating them. With the ordinary membership access used by the setup plus these admitted stronger tests, finite critical-index/augmentation searches terminate; a finite union of the selected languages can be enumerated by membership scanning. Thus an ordinary oracle-free requirement would be inappropriate. The actual exhaustiveSemanticOracleAlgorithm (ExhaustiveCharacterization.lean:232) instead enumerates a semantically defined set using infiniteEnumeration. No typed relative interface or subset-oracle reduction is concluded at line 301: the documented gap survives.

For Proposition 6.3, WeakAngluinEnumeration includes one Computable₂ emitter; weakTellTaleApproximation_of_enumeration explicitly uses stageContents emit (MembershipExhaustive.lean:49,64). Finite stageContents, finite candidate tests and a minimum are computable with membership access. enumerateOracleLanguage searches for a member at or above a requested bound; infinitude guarantees finite termination for each output. Consequently the implementation explanation is mathematically credible, using no subset/finiteness oracle. The theorem at line 328 still concludes only an exhaustive semantic algorithm. Its dependent relative-computability certificate remains absent, rather than being supplied by a comment or by the emitter hypothesis.

These are informal realizability arguments, not Lean-checked new results. No ordinary sampler, probability measure or unbounded-query-time bound is inferred.

### Theorem 7: a valid repair of an invalid inference

Source p. 11 says an infinite query loop continues populating both languages infinitely. A computable rule repeatedly asking the same query forever has infinite trace length but singleton word range, even against two distinct infinite languages. It fails the theorem's termination premise, so this is a counterexample to that proof inference, not to Theorem 7.

The smallest repair is to complete each finite partial assignment to two distinct infinite languages first. Universality forces termination on this legal completion and its extendible common positive prefix. Record its finitely many queried answers and output, then extend the partial assignment. Fresh common inputs make the final languages infinite; a permanent one-sided marker preserves distinctness. Every recorded execution survives subsequent extensions. An output already common is an observed input; otherwise it can be excluded from one side. At a prefix longer than both proposed thresholds, one target therefore fails membership or freshness.

The relevant interfaces actually state finite separated completions (MembershipQueryDiagonalRepair.lean:218), an infinite-run/finite-word-range example (line 306), and a nontermination certificate contradicting the exact guarantee (lines 385,404). CompletionDrivenStep (MembershipQueryGlobalDiagonal.lean:309) records legal temporary infinite completions, finite execution and preserved assignments; theorem_seven at line 823 retains the original closed proposition. This supports a **justified source-proof correction**, without certifying the implementation proof. Equivalence of this total next-action normal form with every partial oracle-Turing-machine representation remains unproved here.

### Feedback: outputs may change, so replay matters

Source Lemma 7.2, p. 28, obtains a strategy whose effective intersections stay nonempty; that need not be the strategy's own output. Simply replacing outputs could change future adversary actions.

The actual coreSelectingFeedbackStrategy (Feedback.lean:799) sends a shadow history to the old query strategy and chooses from the current real effective intersection. feedbackShadowHistory preserves inputs, queries and answers while replacing past outputs. These preserve consistent languages. Against any truthful adversary for the new strategy, replayFeedbackAdversary reproduces its actual input/answer sequence against the old strategy. The interfaces assert shadow equality, query equality, residual equality and consistency (lines 786,834,862,900,914). Therefore the old safety obstruction transfers to the new play while its new output lies in every consistent target. The minimal repair is this strategy transformation, not an assumption that the original output already belonged to the core. **Accepted as a justified implicit source step**, supported by explicit native interfaces; not a proof audit.

### Representation, transport and zero boundaries

The exhaustive API really allows order dependence: two reversed length-two histories have identical sample sets but a function may select their different first entries. Its equality with a literal set-only API is not established. Nevertheless the positive greedy and exhaustive constructions inspect only sample and length: see selectedIndices and ExhaustiveHistoryConsistent/Critical, then focus/augmentation definitions (Nonuniform.lean:72; ExhaustiveCharacterization.lean:27-59,167-190). Negative results exclude the larger prefix class. Thus **qualified representation choice**, not a demonstrated headline failure. A general API equivalence remains unclaimed.

Claim 5.2's Nat/integer adaptation is justified informally by the computable bijection e(0)=0, e(2k+1)=-(k+1), e(2k+2)=k+1. Mapping inputs/outputs pointwise preserves ranges, finite sets, target equality, sample cardinal and prefix dependence; it maps universe and every one-hole language exactly to the integer class. Effective functions remain effective under this explicit encoding. Native integerSweep_bijective supports a bijection, but there is no named Lean breadth-transport certificate. **Faithful representation change; transport argument informal**, not an absence of the substantive separation.

For Definition 6, a single infinite language already makes the collection of finite candidate intersections empty. Replacing its printed maximum by max({0} union candidate sizes) is the smallest explicit convention; Lean's Finset.sup implements it. Positive-level dimension equivalence likewise determines equal nonnegative extended-natural dimensions under sup(empty)=0. It deliberately avoids false zero-obstruction identities: for disjoint infinite even/odd languages, the empty sample has finite closure, while after any first positive input all consistent languages are one infinite parity class, so no empty fresh intersection occurs. Proposition 7.1 is correctly restricted to positive levels (NoFeedbackDimension.lean:257). Target 5's boundedness is unaffected. **Accepted conventional completion, without claiming literal zero-predicate equality.**
