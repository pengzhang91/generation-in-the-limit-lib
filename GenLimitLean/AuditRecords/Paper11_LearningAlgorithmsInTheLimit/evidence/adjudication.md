## Lemma 9/25: literal failure and repaired readings

The source pp2,4,8 defines general recursive functions as **partial**, permits every model subclass M⊆MD, and quantifies all input sources contained in a teacher's defined domain. Definition 7 requires a fixed representation R eventually, with `S(R)|IM=fM|IM`; it does not require equality outside IM. Definition 8 applies that source-relative correctness after characteristic data. Lemmas 9/25, pp9,20, say distinct restricted functions force a domain or observation distinction within the union of characteristic cores.

Here is an informal counterexample checking the standing assumptions without relying on finite domains or empty cores:

- Set D=I=ℕ. Let M compute zero on every input. Let N compute zero on even inputs and diverge on odd inputs. Both are ordinary finite-description partial-computable programs; both defined domains are infinite.
- Use model class {M,N} and IOO auxiliary information α=ε. These functions are distinct as partial functions on I because their domains differ, not merely because their codes differ.
- Take the computable representation set of all finite TM descriptions, containing both programs and an ordinary constant learner that always emits that one code. For **every** source J⊆DM and every exhaustive order, its hypothesis restricted to J equals M restricted to J. For every J⊆DN it likewise equals N restricted to J. The representation is stable immediately. No source membership or halting oracle is queried.
- Every admissible observation is genuine and all labels are zero. Infinite presentations exist explicitly for the full teacher domains: n↦n and n↦2n. Arbitrary source/order choices do not affect the constant learner. Empty-source convention is irrelevant.
- Choose both characteristic cores to be the **nonempty** finite set {0}. For every containing valid sample, the same learner remains correct on each teacher's required restriction. Thus both characteristic premises hold, even if finite-data or nonempty-core qualifications are imposed.
- Their union is {0}, contained in both defined domains, and the full IOO examples at 0 agree. Neither alternative in the source conclusion occurs.

No standing totality, infinitude, nonidentifiability or representation restriction found in the source excludes this example. If both teachers were required to have proper partial domains, use zero on the evens and zero on multiples of four, with the first teacher's program as constant hypothesis; the same infinite-domain argument works. If **all** teachers must be total, the example is excluded, but that is a genuine additional hypothesis, not the paper's global convention.

The least repair to the separation premise is to require incompatible values at some **shared defined input** in I. If a core already contains a point outside the common domain, the source's domain-disjunction holds. Otherwise their union is a valid sample for both; characteristic correctness would force one hypothesis to take both incompatible values, giving the contradiction. Alternatively assume both are total on one common source. These are informal arguments, not new Lean-checked theorems.

Lean implements a stronger correctness regime on one common source: `CorrectOn` compares entire Option values, including none. For the nested-domain example, the constant total-zero representation is **not** correct for N at odd inputs, so it is not a native characteristic witness on the common source ℕ. Option-encoding observations alone does not supply the unobserved divergence labels required to apply that stronger premise. The native lemma can support the common-defined-source repair, but the partial-domain case split/restriction wrapper is not an existing target. The registry's “full” label should therefore be restricted to the explicit model or repaired reading. This is neither an unexplained Lean error nor automatic full correspondence to the literal printed lemma. The counterexample uses different partial domains; it does **not** refute Theorem 17, whose source reduction uses total halting machine pairs and can use the common-domain version.

## Concrete computation and representation adjudication

The claim that the learners receive only finite history is supported by actual definitions, not just documentation. At history length t, `enumerationLearner` filters indices 0 through t by a supplied two-argument decidable fitting operation and returns the least fitting one, or 0. A fitting representative is used in convergence hypotheses, not as a learner input. A supplied uniform decider is stronger evidence than separate existential deciders for each history. Nevertheless, an arbitrary simulator/semantic function parameter is not automatically an ordinary computable operation. The proper reading is an executable algorithm relative to those supplied operations, becoming ordinary for effective concrete choices. No new computability label is required when the construction itself supplies those operations.

Corollary 15 does supply the important concrete operations. `TuringProgram` is a finite list of instructions; lookup uses the paired state/symbol code, missing entries halt, configurations start at 1 and halt at 0, and bounded iteration never queries unbounded halting. Although the state datatype is Nat, reachable states lie in the finite set containing 0, 1 and the next-state entries of that finite program. Thus the natural-state representation is not evidence of an infinite-state TM. This finite-support observation is informal; the existing interpreter definitions are exact checked inputs.

Outside the facade, `GenLimit.LearningAlgorithmsLimit.turingCandidateScale_pair` and `GenLimit.LearningAlgorithmsLimit.turingCandidateProgram_pair` state that the candidate `pair scale (encode program)` decodes to that scale and exactly that program. `IsTuringTimeBoundObservation` supplies `∃scale, ∀x∈source, runWithin (scale·bound(x)) io program x = some(value(x))`, as well as input coherence. Together these give **one candidate for the entire source**, with no per-input program selection. Each history checks finitely many candidates, each using a finite recorded budget times its fixed scale. The final criterion is one stable decoded program with `∀x∈source, ∃budget` computing the value. Pointwise final budget witnesses are entirely sufficient for the source's correctness conclusion; their not being presented as a final uniform scale is not a defect.

The alphabet is finite and has explicit encodability/equality instances; output equality is supplied. The actual program-and-scale construction therefore establishes the concrete TM learning result, rather than merely assuming its hard representative-existence step. I accept the PaperMap's full **concrete single-tape specialization** with that qualification. It introduces no oracle, and source Corollary 15 makes no polynomial-time learner promise, so interpreter execution cost need not match simulated step count. Generic `TuringIO` still allows arbitrary initialization/output functions and arbitrary unencoded input/output types. No named canonical standard-string `io` value or separate effectiveness theorem appears in the 516-record export. A canonical effective instance is nevertheless directly constructible: initialize a finite input list on a blank tape; on output reverse the stored left list, append the scanned cell and right list, trim outer blanks, and accept exactly a contiguous string of problem-alphabet symbols. Finite alphabet membership and inverse input-symbol decoding are decidable finite searches. This is an explicit ordinary finite-list algorithm, described here informally rather than added to Lean. For those source string conventions the existing parametric learner is sufficient; a separate computability label is not needed. The generic theorem does not establish that every arbitrary I/O choice is ordinary computable. This is a representation/interface qualification, not a demand to add a redundant algorithm certificate.

For Theorems 12/14 and Corollary 13, the explanations candidly omit q-ECTT and Q-class instantiation. Testing the types confirms more precise boundaries: no Q, canonical size, reasonable encoding or source model class occurs in the abstract bounded-enumeration structure. The same elimination logic can support many such constructions but does not supply them. In particular, positive elimination can specialize to the teacher's defined source with exclusively `some value` labels; these uses of Option do **not** require observing divergence. The issue is the missing uniform class-to-candidate assembly, not a defect in every optional-label formulation. Encoding the source's simulation assumption as a hypothesis would not require declaring a new physical axiom. The smallest follow-up is to construct the uniformly clocked candidate family and prove class membership supplies a fitting candidate, then specialize the existing convergence theorem. Named complexity-class labels alone would not do that work.

## Testing the remaining explanations and proposed repairs

**Budget-first minimality.** The TimeBounds comments and registry already limit the minimum-index diagnostic to an unjustified inference. That limitation is correct. The definition gives representation 0 threshold 10 and representation 1 threshold 2; its four checked conjuncts neither contain a learner nor instantiate the source's fixed size-ordered TM enumeration. They show that being first at a feasible budget does not entail being first among representations admitted at larger budgets. I accept a source-proof qualification, not a refutation of the main learning theorem or a proved counterexample to every concrete enumeration. The smallest repair is to drop global minimum-state prose, or identify the first representation at the eventual feasible budget. Informally, monotonically increasing feasible budgets bounded by one successful budget eventually stabilize; finite elimination then selects a correct candidate there. Native fixed scale/program candidates offer another valid construction, but their pairing order is not automatically the source's budget-first order. No runtime or minimum-state guarantee is added by that repair.

**Rational enumeration and reduction.** The comment that finiteness may be imposed only where needed is mathematically reasonable: generic convergence does not need `Fintype State`. A finite reachable closed support could also replace global state finiteness. Neither condition, an all-finite-machine coding, nor an exhaustive family is established by the given-family theorem. For example, a family containing only a one-state constant-zero machine satisfies the native theorem; the different rational constant-one machine is not a target of that instance. Thus finiteness missing from a general lemma is not itself a bug, but the family theorem is not all-rational coverage until the missing family is supplied.

There is also a genuine disclosed source repair: Appendix D p22 writes an ordering onto all A* while simultaneously taking samples inside arbitrary I. The intended ordering is onto I. `Covers` enforces both membership and exhaustion, so this correction matches context. It does not establish the rest of the reduction. Whole output lists supply prefix outputs; final-symbol rational learning on an unchanged restricted source does not supply those automatically. Actual tape runs must generate the scanned-history source, the learning reduction must manage prefixes, and a learned finite representation must be interpreted as a task-computing TM with appropriate halting/output conventions. The local PolicyMachine equality contains none of these bridges. The separate concrete interpreter does not connect to it through an existing exported theorem. The registry's partial disposition is justified; its “finite-state” component wording should be read as a finite-instance specialization, not a property forced by arbitrary State.

**Halting lower bounds and mass.** Comments explicitly omit the machine reduction, so Stage 2 did not discover a concealed claim of a completed noncomputability proof. For each fixed threshold k, a finite-history learner for the native Boolean family can return true exactly after seeing `(k,true)`. On finite histories this is an ordinary scan; its extension to arbitrary observation sets is only a semantic set function. Both models have computably chosen characteristic core {k}; the native combined mass is then 2(k+1). This informal example satisfies the local pattern and demonstrates why rows 9–10 alone cannot rule out computable cores or every computable representation-dependent bound. No actual TM representation, effective halting-instance construction, shared full PTO behavior or linear-time guarantee is supplied by those targets. The linear-time strengthening needs its own architecture-sensitive construction; this review has not certified the source's runtime assertion or disproved it.

The source's mass includes input, output and auxiliary trajectory encodings. Native `inputMass` instead sums n+1 over numerical inputs, and the transfer theorem keeps one arbitrary input-set measure unchanged. Forgetting can preserve the characteristic **inputs** while their full data lengths change: append an arbitrarily long ignored auxiliary string to observations of a two-model one-input learning problem, then erase it. The same necessary input core may have far larger rich-data mass. This informal cost example is not a counterexample to the source's concrete Corollary 18; it shows why erasure alone is not a mass-comparison proof. A concrete input-length obstruction plus “input length ≤ full data length” could supply the needed lower-bound route, but that assembly and its representation quantifiers remain absent. Ordinary computable β and ordinary computable core selectors, rather than source-relative oracle versions, are the missing source conclusions.

**Tagged construction, covers and MSM.** The tagging definitions genuinely produce fresh disjoint symbols and the two stated actions, preserve the final normal state on encoded words, and double their length. Totalization cases outside matching tags are not visited by those word simulations. They neither encode an arbitrary total-recursive function's actual teacher program nor prove tape-output/halting preservation. The cover theorem genuinely gives all three stated conjuncts, but supplies its witness map and used transitions. Two required samples can be delayed arbitrarily long in a covering stream by repetitions; this does not refute a two-sample favorable curriculum bound.

The MSM explanation is also correct about being conditional. I rechecked initial soundness, a good candidate of score at least 2 at every sound incomplete configuration, unintended scores at most 1 there, preservation under intended merges, terminality of sound complete configurations, and strict decrease for every maximum-positive choice, including outside the sound region. Under that gap, no maximizing bad candidate is possible. Without it, two candidates of equal score 1, only one intended, already show why maximizing alone gives no intended-choice guarantee. That informal abstract example does not show the tagged source algorithm fails. Supporting native theorems do cover soundness along runs and well-founded descent; they still do not define the observation tree, cascade quotient, actual similarity score or prove its concrete gap. Defining Complete as mere source-equivalence would also need care, because the paper permits subsequent harmless mergers whereas the conditional theorem requires Complete to be terminal. The smallest valid source repair is an explicitly conditional theorem with the actual sufficient hypotheses. The native theorem implements that repair abstractly; the unconditional Theorem 21 remains unresolved/unformalized, not proved false.
